## 🧠 记忆系统真正生效（关键修复）

这次针对「用了很久记忆却一条都没写入、新对话完全不知道旧内容」做了深度排查，修掉两个导致记忆**从未真正跑起来**的 bug：

### 1. 记忆提示词改成「动态注入」，且总是注册

之前记忆上下文用的是**启动时的一次性冻结快照**，而且**只有启动时记忆非空才会注册**进系统提示词。你启动时记忆是空的 → 提示词里根本没有记忆这一节 → 之后无论写进多少记忆，**新对话都永远看不到**（这就是“开新对话问上个对话在聊什么，它说不知道”的直接原因）。

现在改成：记忆提示词**总是注册**，且是**动态函数**——每次组装提示词时实时读当前记忆。记忆一旦有内容，新对话立刻能看到。

### 2. 工具 / 提示词 / 复习的注册互相隔离，复习无条件挂载

之前这几样注册在同一个异步流程里，只要其中一个在桌面宿主上下文抛错（很可能是访问了未声明的服务），**后面的复习就永远不会挂上**——这就是 `review-state.json` 里 `lastReviewedAt: 0`（复习从没成功跑过）的根源。

现在：`memory` 工具、`/memory` 命令、提示词注入、**自动复习**各自独立 try/catch——任何一个失败都只影响自己、打日志，**不再连带掐死复习**；复习只要配置开启就一定会尝试挂载。

### 3. 更透明的诊断

每处失败现在都会输出明确的日志（`dsh-plugin-desktop: could not register …` / `background memory review failed: …`），下次如果还有问题，我们能直接从日志和 `review-state.json` 定位，而不是猜。

## 验证方式

1. 升级到 2.0.11；
2. **正常聊 ≥4 个非平凡回合**（不要只回「ok / 继续」）；
3. 检查 `C:\Users\Administrator\.dsh\profiles\desktop\memory\`：
   - `review-state.json` 出现 `lastRunAt` / `lastOutcome`（说明复习真的跑了）；
   - `MEMORY.md` / `USER.md` 出现内容；
4. 开新对话问「我们上个对话在聊什么 / 你知道关于我的什么」——现在系统提示词里有记忆，模型应该能答出来。

> 如果升级后复习仍然不跑（`review-state.json` 仍只有 `lastReviewedAt: 0`），把 设置→记忆 面板的「自动复习」状态 + `review-state.json` 内容发我，说明 `agent/turn-stopping` 事件没有送达宿主，我们直接上下一步方案（把复习挂到会话事件上）。

## What's new in 2.0.11

- Memory system-prompt section is now **always registered and dynamic** (function text read at every prompt assembly), so new conversations actually see the current memory — previously a frozen snapshot that was only registered when memory was non-empty at startup, which is why new sessions never knew anything.
- Tool / command / prompt / review registrations are now isolated (each in its own try/catch with a clear log), and the automatic review loop is always attached when enabled — a failure in one registration can no longer silently kill the review.
- Added explicit diagnostics so any remaining failure is identifiable from logs and `review-state.json`.
