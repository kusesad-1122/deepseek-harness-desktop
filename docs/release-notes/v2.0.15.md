## 🧠 全局记忆的真正正解：把记忆挂进你「实际聊天」的运行时

这版是记忆系统的**架构级修复**，基于你上一个实测（新会话里模型自己说「没有 memory 工具，只能手动读文件」）定位到根因：

**记忆的 `memory` 工具、提示词注入、自动复习，之前全部注册在「宿主进程」；但你聊天走的是「Web 渲染进程」——两个运行时不通。** 所以记忆能写入（文件都在）、但永远进不了你新会话的工具箱和提示词。

### 这版做了什么

1. **新增渲染进程完整插件 `dsh-plugin-desktop/memory-web`**，通过 profile bundles 加载进**你真正聊天的那个运行时**（和 modlens、rea、super-injector 同一机制）。它负责：
   - **`memory` 工具** → 直接出现在你的工具清单里，可读/写（HTTP 桥接宿主内存存储，同一套锁/预算/去重/审批）；
   - **动态提示词注入** → 每次组装实时读记忆（画像 + 笔记 + 最近会话摘要），新会话自动带出；
   - **自动复习** → 挂到你聊天真正触发 `agent/turn-stopping` 的地方。
2. **宿主新增 `/write` 路由**，供渲染进程桥接读写。
3. **profile 自动注册**：应用下次启动会在 profile 的 bundles 里加入 `dsh-plugin-desktop/memory-web`，并把它自己加入 profile 依赖（file: 链接），确保渲染进程能解析到。

### 验证方式（关键：需要重启应用，让 profile 重新装配）

1. 升级到 2.0.15，**重启应用**（首次启动会自动把 `memory-web` 写进 profile bundles 并安装依赖）；
2. 开新会话，**先问它：「你现在有哪些工具？有没有 memory 工具？」**——现在应该**有** `memory` 工具了；
3. 再问「我是什么样的人 / 我们之前聊了什么」——它应该**直接引用记忆作答**（不再需要手动读文件）。

> 说明：`memory-web` 加入 profile bundles 后需要应用完成一次依赖装配（pnpm install）才能被渲染进程加载；如果首次重启后工具还没出现，**再重启一次**让它完成装配。

## What's new in 2.0.15

- Architectural fix for global memory: the `memory` tool, dynamic system-prompt injection, and the automatic review were registered in the Electron Host, but your conversations run in the Web renderer (a separate Cordis) — so they never reached your agent (confirmed by your session: the model had no `memory` tool).
- Added a renderer-side plugin `dsh-plugin-desktop/memory-web` loaded via profile bundles into the runtime where your conversations actually run: it registers the `memory` tool, a live dynamic memory prompt section, and the review loop on `agent/turn-stopping`, bridging to the Host MemoryStore over HTTP.
- Host added `/dsh-desktop/memory/write`; the desktop app now auto-registers the bundle in the profile and self-links the package so the renderer can resolve it.
