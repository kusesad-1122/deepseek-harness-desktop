## 🔧 更新弹窗彻底加固（不再黑屏、不再卡死、不再混杂原生/自绘）

针对你反馈的三个更新弹窗问题，根因是同一个：**自绘弹窗在打包环境里页面脚本没能初始化**——所以「检查更新」命中新版时自绘弹窗创建失败回退成了原生弹窗；下载进度窗则直接黑屏、还没法关闭。

这版做彻底加固：

1. **弹窗页面从本地临时文件加载**（原来用 `data:` URL，打包环境不可靠）；
2. **渲染验证**：页面加载后先探测脚本是否真的跑起来了（`typeof window.__mount === "function"`），**没跑起来就立刻销毁并干净回退原生**——绝不显示黑屏；
3. **进度窗不再吞错误**：任何失败立即销毁窗口并回退（托盘继续显示下载进度），彻底消除「黑窗 + 关不掉」；
4. 效果：
   - 自绘弹窗渲染成功 → 「检查更新」「更新可用」「下载中」「安装就绪」全程 Hermes 风格，风格统一；
   - 自绘弹窗渲染失败 → 「检查更新/更新可用」回退原生对话框，下载进度回退托盘显示，**绝不会出现一个黑的死窗口**。

## 验证方式

1. 升级到 2.0.14（需要先升级到本版才能看到本版弹窗——请直接从 Release 页下载覆盖安装，或用托盘/设置检查更新到本版）；
2. 等自动提示或点 设置→关于→检查更新，命中新版时：
   - 若自绘弹窗正常：看到 Hermes 风格「⚠ 更新可用」窗；
   - 若回退：原生「Update Available」窗（可接受，但不再是黑屏死窗）；
3. 点「立即更新」→ 下载过程：
   - 自绘正常：琥珀色进度条 + 百分比 + 阶段；
   - 回退：无进度窗（托盘显示进度），下载完弹「Restart and Install」；
4. 全程**不会再出现全黑、关不掉的窗口**。

> 如果这版自绘弹窗在你的打包环境仍然回退原生（没黑窗，只是不漂亮），请告诉我——那就说明 Electron 打包环境对自绘 HTML 弹窗支持不佳，我下一版直接把更新流程整体改成原生对话框的 Hermes 配色主题，风格统一且 100% 可靠。

## What's new in 2.0.14

- The styled update dialog now loads its HTML from a local temp file instead of a `data:` URL (packaged-build reliability), and verifies the page script actually initialized (`typeof window.__mount === "function"`) before showing. On any render failure the window is destroyed immediately and the caller falls back to native — a black, unclosable dialog is never shown again.
- `progress()` no longer swallows failures: it destroys the window and rethrows so the download continues with tray progress instead of a dead black window.
