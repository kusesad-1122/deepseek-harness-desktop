## 根治：切会话/进设置无响应（主进程阻塞）

### 1. 会话投影缓存迁移到 SQLite 后端

- 定位到卡死根因：`session_projcache` 域挂在 JSON 存储上，该后端**每次写入都全量 `JSON.stringify` 整个文件并原子替换**。缓存已增长到 ~48MB，而点开长会话（冷读回写）、会话 turn/end、关闭会话都会强制触发 checkpoint → 主进程事件循环被阻塞数秒，所有页面 IPC 无响应
- 现通过桌面补丁层把该域路由到官方 SQLite 后端（`@deepseek-ai/dsh-storage-sqlite`）：一次写 = 一行更新，彻底消除全量重写；其余域仍走 json 默认后端
- 首次启动 SQLite 中介质为空：投影按官方 write-back 自愈机制从会话日志自动重建，无需手动迁移

### 2. 版本

- 2.0.29 → **2.0.30**
- `fix(host): session_projcache 路由 SQLite 后端，消除大缓存全量重写导致的整页无响应`

## English

**Root-cause fix for multi-second UI freezes**

- The session projection cache domain was served by the JSON storage backend, which republishes the whole pretty-printed file on every write. With a ~48MB cache, forced checkpoints (opening a long conversation, turn/end, disposal) blocked the Host event loop for seconds, stalling IPC and freezing every page.
- Desktop patch layer now routes `session_projcache` to the official SQLite backend (one row per write). Other domains remain on json. First launch cold-rebuilds projections from session logs automatically.
