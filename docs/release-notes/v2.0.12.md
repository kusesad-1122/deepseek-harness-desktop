## 🧠 记忆系统这次真正打通了（根因已实锤）

上一版（2.0.11）加固后，自动复习**终于开始跑了**，但在你机器上暴露出最后一个根因——`review-state.json` 记录到：

```
lastOutcome: "error"
lastError: 'Error: cannot get property "llm" without inject'
```

**原因**：记忆插件只声明了 `inject: ['desktopProfiles']`，但复习器要用 `ctx.llm.stream`、提示词注入要用 `ctx.systemPrompt.section`、`memory` 工具要用 `ctx.tools.register`、`/memory` 命令要用 `ctx.commands.register`——这四个服务都没在 `inject` 里声明，Cordis 的服务守卫直接拒绝访问（`cannot get property X without inject`）。这既让复习一调用 LLM 就报错，也让工具/提示词/命令静默注册失败——正是“聊多少轮都写不进记忆、新对话什么都不记得”的完整链条。

**修复**：把 `systemPrompt` / `tools` / `commands` / `llm` 全部加进插件的 `inject` 声明。一行改动，让整条链全部生效：
- 自动复习 → 真正调用 LLM → 把有价值内容写进 `MEMORY.md` / `USER.md`；
- `memory` 工具 → agent 能主动读写记忆；
- 记忆提示词 → 动态注入每个新会话（v2.0.11 已改好，现在能真正注册上了）；
- `/memory` 命令 → 查看/审批/开关。

## 验证方式（这版请务必实测）

1. 升级到 2.0.12；
2. 正常聊 ≥4 个非平凡回合（别只回「ok/继续」）；
3. 检查 `C:\Users\Administrator\.dsh\profiles\desktop\memory\`：
   - `review-state.json` 出现 `lastOutcome: "ok"`（不再是 error）；
   - **`MEMORY.md` / `USER.md` 真的出现内容**；
4. 开新对话问「我们上个对话在聊什么 / 你知道关于我的什么」——现在提示词里有记忆，模型应该能答出来。

如果这版还是不行，`review-state.json` 里的 `lastError` 会直接告诉我们断在哪，不再靠猜。

## What's new in 2.0.12

- Declared `systemPrompt`, `tools`, `commands`, `llm` in the memory plugin's `inject`. The Cordis service guard was rejecting every undeclared harness service access (`cannot get property "llm" without inject`), which is the confirmed root cause: the automatic review errored on the LLM call, and the memory tool / dynamic prompt section / `/memory` command silently failed to register. With the services declared, the whole memory stack now works end-to-end.
